# ТЗ для приложения Android: вход по QR и уведомления без вопроса (контракт 1.4)

Для `crm-ashbyte-android`. Контракт — `docs/ANDROID_CONTRACT.md` **1.4**, схема
входа — `docs/QR_LOGIN.md` в `crm-ashbyte`. Решения владельца 12.11. Константа `BuildConfig.CONTRACT = "1.4"`.

## Зачем
1. Сотрудник входит на телефоне, отсканировав QR с компьютера, где он уже вошёл, — без логина и пароля.
2. Сотрудник входит на компьютере, отсканировав телефоном QR на форме входа компьютера.
3. После любого входа телефон получает уведомления сразу, без вопроса «Подключить уведомления?».

Логин, пароль, подтверждение и 2FA остаются на странице CRM в WebView. Приложение только сканирует код и открывает
адрес из него.

## Что сделать

### 1. Сканер QR (§3.4)
* Свой экран: превью камеры, рамка, «Наведите камеру на QR-код на экране компьютера», кнопка «Закрыть».
* Библиотека — без Google Play Services: телефоны без них есть (CameraX + ZXing `core`, либо ML Kit с моделью внутри
  APK — на выбор приложения, если APK вырастет не больше чем на 3 МБ).
* Разрешение `CAMERA` — при первом открытии сканера. Отказ — «Без камеры вход по QR недоступен» и «Открыть
  настройки».
* Принимается только адрес `http(s)://<хост>[:<порт>]/qr#in.<token>` или `…/qr#out.<token>` (`token` —
  base64url, 43 знака). Иное — подсказка «Это не код входа AshCRM» под рамкой, сканер остаётся открытым.
* Токен и адрес из кода не пишутся в журнал.

### 2. «Вход по QR» на экране адреса портала
* Кнопка под полем адреса. Сканер → код → диалог «Подключиться к `<хост>`?» → портал сохраняется как введённый
  вручную (те же проверки §1: `http://` только для локальной сети) → WebView открывает адрес из кода целиком.
* Дальше всё делает страница `/qr`: ждёт подтверждения на компьютере, спрашивает код 2FA, входит.

### 3. Мост `scan` (§7.1)
* `{t: "scan"}` от страницы `<CRM>` — открыть сканер.
* Код с тем же портом, схемой и хостом, что `<CRM>`, — открыть адрес в своём WebView (это страница CRM).
* Другой портал — «Код другого портала: `<хост>`», ничего не открывается.
* «Закрыть» — вернуться на страницу как была.

### 4. Подключение без вопроса (§3)
* После моста `login` и при запуске, если страница вошла, а телефон не подключён, — открыть
  `<CRM>/desktop-connect?app=android&auto=1&challenge=…&state=…&device=…`. Страница сама перейдёт на
  `ashcrm://connect?code=…` — дальше как сейчас (`POST /auth/desktop/token`).
* Подключение — в WebView, как сейчас; после него вернуться на страницу, откуда был вход (`/` если нет).
* `ashcrm://connect?cancel=1` больше не приходит от CRM 1.4; обработку оставить для CRM 1.3.

### 5. «Для работы нужны уведомления» (§3.5)
* После подключения, если нет `POST_NOTIFICATIONS` (Android 13+) или уведомления приложения выключены в системе:
  экран (не диалог «да/нет») — «Для работы нужны уведомления: без них вы не узнаете о новых сообщениях и клиентах,
  пока CRM закрыта» и одна кнопка **«Разрешить»** → системный запрос.
* Отказ или «Больше не спрашивать» — тот же экран: «Открыть настройки» (настройки уведомлений приложения) и «Позже».
  «Позже» — до следующего запуска.
* Каналы уведомлений выключены по отдельности — не трогать, это выбор сотрудника.

## Совместимость
* CRM 1.3 (`GET /app/android` → `contract` 1.3): кнопки «Вход по QR» на экране портала нет, `auto=1` CRM не знает
  — покажет «Подключить?», как раньше.
* Страница CRM 1.4 показывает «Вход по QR» в приложении только с `contract ≥ 1.4` в User-Agent.

## Проверка
1. Экран портала → «Вход по QR» → код с компьютера (меню аватарки → «Вход по QR») → «Подключиться к …?» →
   на компьютере «Разрешить» → телефон вошёл, уведомления подключены без вопроса, пришёл экран «Разрешить».
2. То же с включённой 2FA: после «Разрешить» на компьютере страница спрашивает код.
3. Вошедший телефон: профиль → «Вход по QR» → код на форме входа компьютера → «Войти на компьютере?» → «Войти» →
   компьютер вошёл.
4. Код другого портала со страницы CRM — «Код другого портала», ничего не открылось.
5. Посторонний QR (ссылка на сайт) — «Это не код входа AshCRM».
6. Вход паролем — уведомления подключились без вопроса.
7. Отказ в `POST_NOTIFICATIONS` — экран с «Открыть настройки»; после включения в настройках экран не показывается.
8. Отказ в `CAMERA` — «Открыть настройки».
